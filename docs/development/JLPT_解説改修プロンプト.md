# JLPT N2 言語知識（文字）解説文 改修プロンプト

このファイルを新しいセッションの冒頭に貼り、対象JSONを添付して使う。

---

## 0. 依頼文（そのまま貼る）

添付のJLPT N2 言語知識（文字）問題JSONについて、`explanation` フィールドを以下の仕様で全面的に書き直してください。
`question_id` `category_*` `difficulty` `question_text` `option_*` `correct_answer` は変更しないでください。
出力は入力と同じキー構造のJSONで、100問単位で返してください。

---

## 1. データ構造

```json
{
  "question_id": "JLPT_N2_LK_Ch_001",
  "category_lv1": "言語知識",
  "category_lv2": "文字",
  "category_lv3": "漢字読み",
  "difficulty": 3,
  "question_text": "契約を<u>更新</u>する。",
  "option_1": "こうしん",
  "option_2": "こうじん",
  "option_3": "くんしん",
  "option_4": "ぐんしん",
  "correct_answer": "こうしん",
  "explanation": "..."
}
```

- `category_lv3` は `漢字読み`（漢字→読みを選ぶ）または `表記`（読み→漢字を選ぶ）
- `difficulty` は 1（易）〜5（難）
- `question_text` の `<u>` タグが出題箇所
- `explanation` 内の改行は `<br>` タグ

---

## 2. 解説文の必須構成

以下の4要素をこの順で、`<br>` 区切りで書く。

| 順 | 要素 | 目安 |
|---|---|---|
| 1 | 正解の提示 | 25字 |
| 2 | 漢字のポイント（音訓・濁音・促音・字義） | 35字 |
| 3 | 語の意味 | 25字 |
| 4 | **閉じの文＝使用場面 + 難易度を1文に統合** | 35字 |

### 文字数の目標

| 枠 | 目標 | 上限 |
|---|---|---|
| 通常枠 | 120〜130字 | 145字 |
| 厚め枠 | 170〜180字 | 195字 |
| 全体平均 | 130字前後 | — |

※ `<br>` タグを除いた本文の文字数で数える。

## 3. 選択要素（1問につき最大1つ）

### 3-1. 既知語アンカー（適用目安：6割）

難しい漢字を、学習者が既に知っている**N3以下のやさしい熟語**に紐付けてから説明する。要素2に融合させる。

```
「刷」は「印刷（いんさつ）」の「刷」です。
「拠」は「根拠（こんきょ）」の「拠」。「こ」とは読みません。
「察」は「観察（かんさつ）」の「察」ですが、後ろに「ち」が来て「さっ」と詰（つ）まります。
```

- アンカーが見つからない語には無理に付けない
- 同じセット内で既出の語をアンカーにできると効果が高い

### 3-2. 同音異義語の補足（適用目安：2割）

**自動挿入は禁止。学習価値の高いものだけを選ぶ。**

```
同音の「照明」は部屋のあかり。文の意味で見分けます。
同音の「救命」は命を救うこと。音が同じでも意味は全く違います。
同音の「最少」は数がいちばん少ないこと。大きさなら「最小」です。
```

採用基準：

- ✅ ビジネス・日常・文章で実際に使われる語（証明↔照明、検討↔見当、収拾↔収集、避難↔非難、創造↔想像、主張↔首長）
- ❌ 意味が遠く実際には混同しない語（昇降↔商工・将校）
- ❌ 教材に不適切な語（精巧↔性交 など）
- ❌ 一字の訓読み（触↔二・布・負）

毎問入れるとテンポが悪くなるため、2割程度に抑える。

### 3-3. 慣用句・ことわざ一言（該当時のみ）

意味を説明せず、直前の語釈に並べるだけ。

```
ことわざなら「転（ころ）ばぬ先（さき）の杖（つえ）」。
ことわざなら「備えあれば憂（うれ）いなし」。
四字熟語（よじじゅくご）なら「暗中模索（あんちゅうもさく）」。
```

JLPT本試験でもことわざ・故事成語が問われるため、その補完を兼ねる。

### 3-4. 厚め枠（全体の1割弱）

**高頻度語の初出のみ**に適用。セット全体で5回以上出現する語の、最初に出てくる1問。

- 2回目以降は通常枠に戻し、別の切り口で書く
- 厚め枠の末尾に「この語はこの後も繰り返し出ます」と入れて、以降への橋渡しにする
- 20回以上出る語でも切り口は10通りで一巡させ、以降は繰り返しを許容する

## 4. 閉じの文（使用場面 × 難易度）

使用場面タグと難易度コメントを**1文に統合**する。2文に分けない。

| タグ | 文例 |
|---|---|
| 会話寄り | 場面を選ばず毎日使う語です。会話の中で自然に出るように練習しましょう。基本レベルの問題です。 |
| 書き言葉・ビジネス | 「日程調整」の形でビジネスメールに頻出（ひんしゅつ）。今のうちに覚えたい問題です。 |
| 報道・公的文書 | 「経営破綻」の形で経済記事に出ます。会話ではまず使わない、やや難しい問題です。 |
| 硬い・年配層 | 公的な文書や年配（ねんぱい）の方が好む硬（かた）い表現。読めれば十分な問題です。 |
| 場面を選ばない | 会話でも文章でも使う基本の語。ここは必ず正解したい問題です。 |
| 最近増えている | 「システムを導入する」の形で仕事の場面に増えています。意識して使い始めたい問題です。 |
| 書き言葉↔話し言葉の対比 | 「詳細はメールにて」の形で書類によく出ます。会話なら「詳しく」が自然。基本レベルの問題です。 |

レジスターがはっきりしない語（原因・否定・変更など、全体の3〜4割）は**タグを省いて難易度コメントのみ**にする。「どこでも使えます」の連発を避けるため。

難易度の言い回しは定型文を使い回さず、その問題の性格（促音・濁音・同音異義・訓読みなど）に紐づけて書き分ける。

---

## 5. ルビの基準

- **N2以上の漢字を含む語のみ**にルビを振る
- N3以下（意味・問題・言葉・注意・仕事・時間 など）には振らない
- 形式は `漢字（かな）`。`<ruby>` タグは使わない
- 語単位で振る：`状態（じょうたい）` `環境（かんきょう）` `契約（けいやく）`
- 送りがなのある語は読む部分だけ：`保（たも）つ` `譲（ゆず）る`

---

## 6. 禁止事項

- ❌ 誤答選択肢の羅列（「『けんさく』『かんさく』は間違った読み方です」）
  → 誤りを並べるより、正しい紐付けを一本示す
- ❌ difficultyごとの定型文の使い回し（「標準的なレベルの問題です」の連発）
- ❌ 「したがって、正解は○○になります」という締め（冗長）
- ❌ N5相当の語へのルビ
- ❌ 解説文そのものをスラングや硬い文体で書くこと
  → 解説の文体はN3相当で固定。スラングや年配表現は「解説される対象」として置く
- ❌ 字形・部首の補足（次案として保留中）
- ❌ difficulty値の変更（再採点は別作業）

---

## 7. 出力前の自己チェック

各問について確認する。

- [ ] 解説の冒頭「〜」が `<u>` 内または `correct_answer` と一致しているか
- [ ] `correct_answer` を誤答例として挙げていないか
- [ ] `<br>` が3つ以上あるか
- [ ] 本文が上限字数（通常145字／厚め195字）以内か
- [ ] ラテン文字・キリル文字の混入がないか（`<br>` `N2` `IT` `SNS` を除く）
- [ ] 同じ解説文が重複していないか
- [ ] 解説の日本語がN3相当に収まっているか
