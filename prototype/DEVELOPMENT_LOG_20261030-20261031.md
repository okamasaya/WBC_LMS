### 3.3 Actual版の初回実装

実装上の判断：

- 出題はカテゴリ単位の配分を指定し、その枠内から重複なしで抽出する。
- 問題が指定数より少ない場合、Actualでは勝手に出題数を減らさず、開始前にエラーとする。

- 回答を変更した場合、旧回答に対する自信度を消して再入力できるようにする。
- 回答はブラウザのメモリ内で保持する。再読み込み後の復元・サーバー保存は実装していない。

検証では、出題配分、回答・自信度の保持とリセット、確認フラグ、番号移動、回答取消、試験中の解説非表示、終了確認、一括採点、時間切れ、モバイル幅、設定不備・問題不足を確認した。

### 4.2 新Drillを共通conf JSONから起動

- 共通情報：画面名、試験情報、問題ファイル、対象カテゴリ、スキル定義。

パスの基準も明確にした。

- confの指定はHTMLからの相対パス。

## 6. モード差と、変更してはいけないデータの意味

| 項目 | Drill | Actual |
| --- | --- | --- |
| 出題条件 | 開始前にカテゴリ・難易度・問題数を選択 | confで決めたカテゴリ別配分 |
| 正誤・解説 | 自信度ありなら入力後、なしなら回答直後 | 終了後のみ |
| 回答変更 | 回答確定後は変更不可 | 終了まで変更可能 |
| 制限時間 | 通常の練習ではなし | 期限時刻で自動終了 |
| 問題不足 | 範囲内の存在する問題までに減らす。0問は開始不可 | 指定数に不足すれば開始不可 |
| 思考時間 | 確定前の累計。自信度入力を含み、解説閲覧は除く | その問題の表示時間の累計。再訪・終了確認中を含み、期限で打ち切る |
| 終了後 | 解説・理解度・復習フラグ・レポート・CSVは共通 | 同左 |

後続の理解度推定に向け、次の意味を維持する。

- `confidenceLevel` は回答時の自己申告。1が自信あり、4が直感に近い。確率値ではない。
- `understandingLevel` は解説を読んだ後の自己申告。0〜3、未入力はnull。推定値ではない。
- `isAnswered` で未回答と不正解を区別する。未回答の `isCorrect` もfalseになる。
- `answeredAt` は最後の回答選択・確定時刻で、未回答はnull。
- 試験中の確認フラグと終了後の復習フラグは別々に保存する。
- `skillId` は現状ではカテゴリLv3単位。推定に適した粒度かは別途検討する。
- 現行Drill・Actualで学習者IDが未設定ならnull。旧drillの仮IDを実在の学習者識別に使わない。

```sh
# 依存関係の点検と単体テスト
scripts/check-standard.sh

# 既定構成の実行ファイル一覧
node scripts/audit-standard-runtime.mjs --json

# 別ターミナルでHTTPサーバーを起動
python3 -m http.server 8000 --bind 127.0.0.1

# サーバー起動中にブラウザ検証も実行
scripts/check-standard.sh --browser
```

ブラウザ検証にはPlaywrightとChromiumが必要。別環境では依存ツールを用意する。必要なら `CBT_TEST_CHROMIUM` と `CBT_TEST_BASE_URL` で実行ファイル・サーバーURLを指定する。

今回の開発記録の追加自体は文書変更であり、上記の検証結果は記録対象コードに対して実施した過去の結果である。
