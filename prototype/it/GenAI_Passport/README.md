# 生成AIパスポート：問題作成キット v0.2.0

新しく作成する教材は **`schema_version: "0.2.0"`** に統一します。切り替え型は共通の問題文と末尾の選択指示を分け、通常型は完成した問題文をそのまま使います。教材の作成・校正は利用者側で進め、Codexは形式とエンジンの開発・検証を担当します。

次回の再開時は[作業ログ・引継ぎ（2026-11-10）](WORK_LOG_20261110.md)を参照してください。合意事項、現在の実装範囲、検証結果、次の開発課題をまとめています。

## 問題生成を始める手順

1. [問題・解答例の入力テンプレート](templates/source-material.template.md)へ、元の問題文・正解例・解説・分かる範囲の根拠をまとめます。[生成AIへ渡すプロンプト](prompts/generate-question-bank.md)の「今回の入力」を埋め、対象資料・章・型を指定してください。IDは未指定のまま仮採番で進められます。
2. 入力資料、[最新Schema](question-bank.schema.json)、使う型のJSONテンプレート、[完成例](examples/question-bank.v0.2.0.json)を添付します。既存ID一覧は任意です。完成例は形式の参考で、正式なシラバス照合・内容校正済み教材ではありません。
3. 教材JSONと確認レポートを分けて受け取り、除外テーマ・根拠・元資料からの修正を確認します。最初は少数のテーマで確認し、以後は章・範囲ごとに進めて構いません。
4. 完成したJSONを、例えば`data/generated/ch01.v0.2.0.json`へ保存します。テンプレートの`{{...}}`を残したファイルや確認レポートは、教材JSONへ混ぜません。
5. リポジトリルートで次を実行します。複数ファイルはまとめて指定すると、ファイル間のID重複も検出します。

```sh
python3 scripts/validate-it-bank.py dataへの実際のパス.json
# このリポジトリの完成例を検証する場合
python3 scripts/validate-it-bank.py prototype/it/GenAI_Passport/examples/question-bank.v0.2.0.json
```

検証にはPythonと`jsonschema`（Draft 2020-12対応）が必要です。このクラウド環境の`python3`では利用できます。別環境では、利用するPythonの仮想環境へ`python -m pip install jsonschema`で導入してください。構造検証の成功と、教材内容の正しさは別に確認します。

**現在の実行画面はv0.1.0対応です。** v0.2.0は今回整備した作問仕様であり、エンジンの読込・指示文抽選・通常型・出力の対応は今後の実装です。生成したv0.2.0を今の`conf_GenAI_Passport.json`へ登録しても出題できません。作問用ファイルとして保存してください。動作中の旧サンプルと設定は維持しています。

テンプレートは未記入の骨組みです。`{{...}}`をすべて実データへ置き換え、`chapter`の初期値1も対象章へ直してください。候補を追加するときはオブジェクトを増やし、一意なIDと根拠のある内容を記入します。テンプレートをそのまま教材として使わないでください。

完成例の通常型には、キーの無効化・切り替えと、利用履歴からの影響調査という異なる正解候補を2件、不正解候補を3件用意しています。その回には正解候補のどちらか1件だけを出すため、4択の正解は一つです。旧サンプルと新しい完成例は同じテーマIDを含む比較資料なので、別々に検証してください。

## 共通形式

ルートは`format`・`schema_version`・`exam_id`・`questions`のみです。

| 項目 | 内容 |
| --- | --- |
| `format` | `"it-polarity-pool"`固定。通常型を含むバンクも同じ値 |
| `schema_version` | 文字列`"0.2.0"` |
| `exam_id` | 今回は`"GENAI_PASSPORT"` |
| `questions` | 1問以上のレコード配列。同一バンクに両型を混在可能 |
| `question_id` | 設問ID。作成中は仮ID、確定後は安定したID |
| `question_type` | `"polarity"`または`"standard"` |
| `chapter` / `topic` | 正の整数の章番号／テーマ名。公式シラバス分類とは区別 |
| `question` | 切り替え型では共通部分、通常型では選択指示も含む完成文 |
| `explanation` | その問題全体の共通解説 |
| 各候補の`option_id` / `text` / `explanation` | 候補ID（作成中は仮ID可）／本文／成立理由、または誤りの理由と訂正 |

本文・解説はプレーンテキストです。候補には固定の`correct_answer`や`isCorrect`を持たせません。未知のキーや旧版の`stems`も追加しません。

## 切り替え型：polarity

`question_type: "polarity"`が切り替えONに相当します。別の真偽値フラグは不要です。

- `question`例：`AI研究の歴史におけるダートマス会議について、`
- `instructions.appropriate`：適切側で使える末尾表現の配列。1件以上。
- `instructions.inappropriate`：不適切側で使える末尾表現の配列。1件以上。
- `pools.appropriate`：その文脈で適切な候補。3件以上。
- `pools.inappropriate`：その文脈で不適切な候補。3件以上。

出題方式を決め、そのグループの末尾表現を一つ抽選し、`question + 選んだ末尾表現`を直接連結して完成文にします。空白・句読点・接続語は自動補完しません。「〜について、」の後に「適切なものを一つ選んでください。」などが自然につながるように書きます。

「適切」と「正しい」の置き換えで意味が変わるテーマでは、使える表現だけを登録します。表現は各1件で構いません。二重否定の「不適切でないもの」、相対比較の「最も適切」は初版で使いません。

| 方式 | 抽出 | 選ぶ正解 |
| --- | --- | --- |
| 適切を問う | 適切1件＋不適切3件 | 適切プール所属の1件 |
| 不適切を問う | 適切3件＋不適切1件 | 不適切プール所属の1件 |

適切な内容の候補が、その回のテストでも正解になるとは限りません。どの末尾表現・候補の組合せでも、この関係と問題の前提が変わらないように作ります。

## 通常型：standard

`question_type: "standard"`が切り替えOFFに相当します。

- `question`は「一つ選んでください」などの選択指示も含む完成形。文言の追加や適否の反転は行いません。
- `instructions`はキーごと省略。空オブジェクト・nullも禁止です。
- `pools.correct`は、その完成文に対する正解候補。1件以上。
- `pools.incorrect`は、その完成文に対する不正解候補。3件以上。
- 正解候補から1件、不正解候補から3件を重複なく抽出し、4件をシャッフルします。

正解候補も複数用意できますが、一度に出す正解は1件です。例えば「誤っているもの」を問う通常型では、内容が誤った候補が`correct`に入ります。この型の所属は、完成文への正解／不正解で判断します。

開始画面の適切／不適切／混在の指定は、今後のv0.2.0対応では切り替え型に適用し、通常型の完成文を変更しない仕様とします。

## 品質とID

候補数より正確さを優先します。根拠を説明できる適切・正解候補だけを採用し、件数合わせの言い換えや条件の拡大は行いません。適切・正解候補は無理のない範囲で複数、不適切・不正解候補は5件程度を目安にします。5件は義務・上限ではなく、信頼できる3件・4件で止めても構いません。両プールの件数を揃える必要はありません。不適切候補は関連する誤解を扱い、極端な主張だけで除外できる候補に頼らず、誤りの理由と正しい考え方を説明します。「保証されない」と「不可能」も区別します。

元の問題文・正解例・解説を確認してから、同じ学習範囲内でプールを広げます。元問が「不適切なもの」を問う場合、元問の正解例は切り替え型では不適切プールに属し得ます。元の正解というラベルだけで適切プールへ入れず、元問の前提と内容の理由を確認します。元の解答に疑義がある場合も、無条件に踏襲せずレポートへ残します。

最低件数を信頼できる内容で確保できないテーマは出題対象から外し、JSON外の確認レポートへ理由を報告します。別テーマからの補充・候補の複製・候補不足を隠すための型変更はしません。全テーマが除外された場合は、不適合な空バンクではなく確認レポートだけを返します。

- 候補は単独で読める文にし、「上記」「ほかの三つ」「1と2」「すべて正しい」のように表示順や他候補へ依存させません。
- 作成中は`TMP-Q001`、候補は`TMP-Q001-A01`／`TMP-Q001-I01`、通常型は`TMP-Q001-C01`／`TMP-Q001-W01`などの仮IDを使えます。正式採番は内容レビュー後にまとめて行います。草稿の内容を直すたびに正式IDを取り直す必要はありません。
- 仮IDは一回の出力内で一意にします。複数の草稿を統合する際に全ファイルのIDを整理し、仮IDと正式IDの対応を残します。複数ファイルをまとめて検証すると重複IDは引き続き検出されるため、整理前の草稿は個別に検証できます。
- 章番号とIDの文字列の不一致は、作成中に作問を止める理由にしません。元資料上の位置と暫定事項はJSON外のレポートへ残します。接尾辞は作成上の便宜で、エンジンの判定根拠にはしません。
- 公表・利用済みのIDは草稿扱いで変更しません。正式採番後は、意味を保つ表現修正ではIDを維持し、別の知識・意味・所属への変更では新IDにします。欠番は問題ありません。
- 元資料の誤りは踏襲せず、修正と根拠をJSON外へ記録します。出典・正式な分類・難易度・確認日を捏造しません。法律・サービス仕様は前提と確認時点に注意します。

## 検証と現在のエンジン

`validate-it-bank.py`は、バージョンに対応したSchema、IDの全体一意性、同じ問題内の候補本文重複（NFKC正規化・前後空白除去後）、末尾表現の重複、未置換テンプレート、JSONキーの重複を確認します。本文の意味・根拠・シラバス適合は保証しません。テンプレートは未記入のままでは検証に失敗する設計です。

作問キットの検証はリポジトリルートから:

```sh
python3 -m unittest discover -s tests/drill_IT -p 'test_authoring.py' -v
```

現行v0.1.0の動作確認は次のとおりです。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
# 別ターミナルで
bash scripts/check-it-drill.sh --browser
```

入口は[index.html](index.html)、設定は[conf_GenAI_Passport.json](conf_GenAI_Passport.json)、実行処理は[ITエンジンREADME](../../assets/js/drill_IT/README.md)を参照してください。現在は[data/sample_questions.json](data/sample_questions.json)の旧6テーマ・36候補を使います。旧サンプルは、元資料「生成AIパスポート_新シラバス対応.txt」の第1・2・4章から各2テーマを選んだものです。元資料自体と正式なシラバスの再照合は未実施です。
