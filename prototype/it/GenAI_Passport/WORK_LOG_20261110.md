## 合意済みの教材仕様

ルートは`format: "it-polarity-pool"`、`schema_version: "0.2.0"`、`exam_id: "GENAI_PASSPORT"`、`questions`。両型を同じバンクへ入れてよい。

| 項目 | polarity：切り替えON | standard：切り替えOFF |
| --- | --- | --- |
| `question` | 共通の問題文。例「〜について、」 | 選択指示を含む完成文 |
| `instructions` | 適切側・不適切側に末尾表現の配列を各1件以上 | キーごと省略。null・空オブジェクトも使わない |
| プール | `appropriate`／`inappropriate`を各3件以上 | `correct`を1件以上、`incorrect`を3件以上 |
| 抽出 | 適切を問う：適切1＋不適切3。不適切を問う：適切3＋不適切1 | 正解1＋不正解3 |
| 設問文の生成 | 方式を決め、その側の末尾表現を一つ抽選して共通文へ直接連結 | 完成文をそのまま使用 |

- 別の`appropriate_flag`は追加しない。型は`question_type`で識別する。旧版の`stems`も新教材へ持ち込まない。
- 末尾表現は問題ごとに使えるものだけ登録し、各1件でもよい。文末の自動置換や、問題文の文言からの正誤推測はしない。
- 「適切」と「正しい」の置き換えで意味が変わる場合は表現を限定する。二重否定・相対比較に依存した作問は避ける。
- 4候補を重複なく抽出して並べ替える。IDのA/I/C/Wを解析せず、所属からその回の正解を決める。
- 同じテーマは一演習に一度だけ。生成した方式・末尾表現・完成文・候補・並び順は、戻っても変更しない。
- 開始画面の適切／不適切／混在は切り替え型へ適用する。通常型の完成文と正解を反転させない。混在は各切り替え型テーマで独立に50%ずつ方式を選び、件数半々は保証しない。
- 教材には固定の`correct_answer`・`isCorrect`を保存しない。本文・解説はプレーンテキスト。

### 品質と仮IDに関する最新の優先事項

1. 元の問題文・正解例・解説を確認してから、同じ学習範囲内でプールを作る。元の解答例も無条件に正しいと扱わない。
2. **「元問の正解」と「内容が適切」を区別する。** 元問が不適切なものを問うなら、元の正解例が不適切プールへ入る場合がある。通常型の`correct`も、その完成文に対する正解である。
3. 適切・正解候補は無理のない範囲で複数。不適切・不正解候補は5件程度を目安にする。5件は義務・上限ではなく、信頼できる3件・4件で止めてよい。
4. 両プールの件数は揃えなくてよい。最低件数のために言い換え・条件の拡大・無関係な候補を追加しない。不足時は除外理由をJSON外へ報告する。
5. 不適切候補は実際に起こりやすい関連する誤解から作る。「完全」「必ず」「ゼロ」などの極端な主張だけに頼らない。解説は「保証されない」「一般的にはそうならない」「不可能」を区別する。
6. **IDは後でまとめて整理する。** 草稿は`TMP-Q001`、候補は`TMP-Q001-A01`等でよい。一回の出力内では一意にする。修正のたびに正式IDを振り直す必要はない。
7. 元資料との対応・暫定章番号・修正点はJSON外の確認レポートへ残す。統合・確定時に全体のIDを整理し、仮IDとの対応を残す。公表・利用済みの教材やログのIDは草稿扱いで変更しない。

### GeminiのVAE草稿についてのレビュー経過

チャットで、通常型の初稿（正解1・不正解3）と改稿（正解3・不正解5）を受け取った。候補数の運用は合意したが、改稿をそのまま内容確定・採用したわけではない。JSON全文はGitへ保存しておらず、次回必要なら利用者の提供データを確認する。

- VAEの説明は、入力に対応する潜在変数の分布を推定し、潜在ベクトルをサンプリングすることと、生成時に通常使う事前分布・デコーダの役割を区別する。
- 通常のオートエンコーダーにも連続値の潜在ベクトルはある。「分布にしただけで連続的になり、意味のある補間が保証される」という説明を避ける。
- 「ぼやけの解消が保証されない」を「鮮明な画像の生成は不可能」と言い換えない。ハイパーパラメータも「分布化だけで設定の影響がなくなるわけではない」と説明し、常に手動調整が必須だと断定しない。
- 生成の応用・補間・分布表現の仕組みを同じ正解プールに入れるなら、全候補が問いに答える問題文にする。「できるようになること」だけを問う文では、仕組みの説明が答えとして弱くなる場合がある。
- 章とIDの不一致や候補IDの振り直しは、最新方針により後で整理する。内容レビューを止める理由にしない。

### 3. v0.2.0のエンジン対応（次の主な開発課題）

- **`bank.mjs`**：新Schema相当の型別検証を追加し、`polarity`の指示文抽選・直接連結、`standard`の正解1＋不正解3を実装する。既存v0.1.0経路を維持する形が望ましい。最低件数・ID・本文重複の検証を弱めて通さない。
- **`app.mjs`**：通常型の方式表示・候補の解説ラベルを扱う。現在は`MODE_LABELS[q.questionMode]`と「内容は適切／不適切」の2分類を前提としており、プール名を増やすだけでは通常型を正しく表示できない。通常型で「誤っているもの」を問う場合も想定する。
- **`session.mjs`**：固定出題・回答確定・時間の既存契約を維持する。生成文や候補を画面再表示のたびに抽選し直さない。
- **`results.mjs`**：型、出題方式、選ばれた末尾表現、実際の完成文、候補の所属とその回の正解を記録する。全出力に同じ確定スナップショットを使い、追加項目と出力バージョンの扱いを定義する。教材バージョンと出力バージョンを混同しない。
- **入口・設定**：別設定でv0.2.0を試し、旧サンプルの動作を保って確認してから既定教材を切り替える。利用者の作成データを勝手にv0.1.0へ書き換えない。
