# JLPT 解説文 作成プロンプト（Phase-3）

Phase-2 で品質チェックと修正を終えた問題データに対し、解説文をゼロから作成する工程です。

**前提**：`explanation` 列には Phase-1 が入れた `（Phase-3で作成）` が入っています。問題文・選択肢・difficulty は Phase-2 で修正済みです。

**Phase-2 が未完了なら、先にそちらを終わらせてください。** 壊れた問題文に解説を書くと、問題文を直したときに解説も書き直しになります。

---

## 0. 依頼文（そのまま貼る）

添付の問題データについて、`explanation` フィールドをゼロから作成してください。

- `question_id` `category_*` `difficulty` `question_text` `option_*` `correct_answer` は変更しないでください
- **50問ずつ**処理し、マスターファイルに直接反映してください（中間ファイルは作らない）
- 各バッチで § 8 のバリデータを必ず実行し、エラーゼロを確認してから保存してください
- Phase-2 からの申し送り（頻出語リスト・同音異義語候補・字形ペア・難語リスト）を添付しています
- **閉じの文は、添付の〆文ライブラリ（`closing_patterns_ALL.md` と `groupF_closing_patterns.md`）から選んでください（§6参照）。自分で作らないこと**

---

## 1. データ構造

```json
{
  "question_id": "JLPT_LK_N2_001",
  "category_lv1": "言語知識",
  "category_lv2": "文字",
  "category_lv3": "漢字読み",
  "difficulty": 3,
  "question_text": "契約を<u>更新</u>する。",
  "option_1": "こうしん", "option_2": "こうじん",
  "option_3": "くんしん", "option_4": "ぐんしん",
  "correct_answer": "こうしん",
  "explanation": "（Phase-3で作成）"
}
```

- `category_lv3` は `漢字読み`（漢字→読み）または `表記`（読み→漢字）
- `difficulty` は 1（易）〜5（難）
- `question_text` の `<u>` タグが出題箇所。**「出題語」＝ その中身**
- `explanation` 内の改行は `<br>` タグ

---

## 2. 作業を始める前に

**セット全体を先に把握してください。1問ずつ独立に書くと、必ず同じ説明を繰り返します。**

過去、1問ずつ書かせた結果、729問中264件の解説が完全に同一文になりました。「点検」23問がすべて同じ説明だった、という状態です。

着手前に以下を確認すること。

1. **出題語ごとの出現回数**（Phase-2 の申し送りにある）
2. **5回以上出る語**はどれか → 初出を厚め枠にする
3. **この50問の中に、同じ語が何問あるか** → 事前に切り口を割り振る

---

## 3. 解説文の必須構成

4要素をこの順で、`<br>` 区切りで書く。

| 順 | 要素 | 目安 |
|---|---|---|
| 1 | 正解の提示 | 25字 |
| 2 | 漢字のポイント（音訓・濁音・促音・字義） | 35字 |
| 3 | 語の意味、または問題文の状況説明 | 25字 |
| 4 | **閉じの文＝〆文ライブラリから1つ選ぶ（§6参照）** | 20〜35字 |

### 文字数

| 枠 | 目安 |
|---|---|
| 通常枠 | 120〜135字 |
| 厚め枠（高頻度語の初出のみ） | 170〜195字 |
| 全体平均 | 130字前後 |

**字数は目安です。内容が足りる長さを優先してください。** 字数に合わせて内容を削るのは本末転倒です。

---

## 4. 切り口カタログ【この工程の中核】

**同じ語が20回以上出ることがあります。毎回違う角度から書いてください。**
以下は実際に729問で使い分けた17の角度です。1つの語につき、10通りまでは無理なく回せます。

| # | 切り口 | 例 |
|---|---|---|
| 1 | 漢字の字義・成り立ち | 「綻」は「ほころびる」。縫い目が開くという意味 |
| 2 | 音読み／訓読みの使い分け | 「応」は「応用」では「おう」、「応える」では「こた」 |
| 3 | 濁音・促音・半濁音の変化ルール | 「しゅつ＋はつ」→「しゅっぱつ」。失敗・発表も同じ変化 |
| 4 | **既知語アンカー** | 「刷」は「印刷」の「刷」／「察」は「観察」の「察」 |
| 5 | 同音異義語 | 証明↔照明／究明↔救命／最小↔最少 |
| 6 | 類語との使い分け | 収拾↔収集／適応↔適用／調停↔仲裁↔和解 |
| 7 | 対義語 | 原因↔結果／輸出↔輸入／潜在↔顕在 |
| 8 | コロケーション | 「対応」の前に付く副詞：適切に／柔軟に／迅速に／丁寧に |
| 9 | 使用場面 | 会話／ビジネス文書／報道／公的文書 |
| 10 | 話し言葉↔書き言葉の言い換え | 掲示「触れないで」↔会話「さわらないで」 |
| 11 | ことわざ・慣用句・四字熟語 | 転ばぬ先の杖／備えあれば憂いなし／暗中模索 |
| 12 | 派生語 | 責任者・責任感・無責任 |
| 13 | 品詞の変化 | 飛躍する（動詞）／飛躍的に（副詞） |
| 14 | 能動と受動 | 「恵む」は与える側、「恵まれる」は受ける側 |
| 15 | **問題文中の難語の説明** | 恣意的／入念／仇となる／こまめに／堪能 |
| 16 | 文化的な含み | 「前向きに検討します」は実質的な断り |
| 17 | 語源・由来 | 風呂敷を広げる／引き金となる／瓦解 |

**#15 は特に有効です。** 出題語が既出ばかりの区間でも、問題文の中には未説明の語が必ずあります。そこを拾えば、1問ごとに新しい情報を渡せます。

## 5. 選択要素（1問につき最大1つ）

### 5-1. 既知語アンカー（適用目安：6割）

難しい漢字を、学習者が既に知っている **N3以下のやさしい熟語**に紐付けてから説明する。要素2に融合させる。

```
「刷」は「印刷（いんさつ）」の「刷」です。
「拠」は「根拠（こんきょ）」の「拠」。「こ」とは読みません。
「察」は「観察（かんさつ）」の「察」ですが、後ろに「ち」が来て「さっ」と詰（つ）まります。
```

- アンカーが見つからない語には無理に付けない
- **同じセット内で既出の語をアンカーにできると効果が高い**

### 5-2. 同音異義語の補足（適用目安：2割）

**Phase-2 の候補リストから選ぶ。自動挿入は禁止。**

```
同音の「照明」は部屋のあかり。文の意味で見分けます。
同音の「救命」は命を救うこと。音が同じでも意味は全く違います。
```

採用基準：

- ✅ ビジネス・日常・文章で実際に使われる語（証明↔照明、検討↔見当、収拾↔収集、避難↔非難、創造↔想像、主張↔首長、適応↔適用、受賞↔授賞）
- ❌ 意味が遠く実際には混同しない語（昇降↔商工・将校）
- ❌ **教材に不適切な語**（精巧↔性交 など）← 辞書検索では必ず混ざるので目視で除く
- ❌ 一字の訓読み（触↔二・布・負）

毎問入れるとテンポが悪くなるため、2割程度に抑える。

### 5-3. 慣用句・ことわざ一言（該当時のみ）

意味を説明せず、直前の語釈に並べるだけ。20字前後で収める。

```
ことわざなら「転（ころ）ばぬ先（さき）の杖（つえ）」。
四字熟語（よじじゅくご）なら「暗中模索（あんちゅうもさく）」。
```

JLPT本試験でもことわざ・故事成語が問われるため、その補完を兼ねる。

### 5-4. 厚め枠（全体の1割弱）

**5回以上出現する語の、初出1問のみ**に適用。

- 2回目以降は通常枠に戻し、別の切り口で書く
- 厚め枠の末尾に「この語はこの後も繰り返し出ます」と入れ、以降への橋渡しにする
- 20回以上出る語でも、切り口は10通りで一巡させ、以降は繰り返しを許容する

### 5-5. 字形の罠（誤答に仕込まれている場合のみ）

**誤答選択肢が「部品ひとつだけ違う紛らわしい字」のときに限り**触れる。

```
「徐（じょ）」は「徐々に」の「徐」で、ゆっくりという別の字です。
「除」の「こざとへん」と「徐」の「ぎょうにんべん」で見分けます。
```

誤答に罠がない場合は触れない。書き取り練習を促す補足は、この工程の範囲外。

## 6. 閉じの文（〆文ライブラリから選ぶ）

**閉じの文は自分で作らず、添付の〆文ライブラリから選ぶ。** これにより表現のばらつきを確保し、生成負荷を下げる。

添付ファイル：
- `closing_patterns_ALL.md`（グループA〜E、難易度1〜5）
- `groupF_closing_patterns.md`（グループF：安全・防災・医療、全難易度共通）

### 選び方（3ステップ）

**STEP 1：グループを判定（正解語ベース）**

`correct_answer`（正解語）の意味で、その語がどの場面の語かを判定する。文中の背景語ではなく、**問うている語そのもの**で決める。

| 群 | 正解語がこういう意味なら |
|---|---|
| **F** 安全・防災・医療 | 事故・災害・救助・応急・避難・予防・点検・警戒（→ `groupF`へ） |
| **D** 報道・公式・法律 | 発表・政策・法律・選挙・警察・改正・報道 |
| **C** ビジネス | 契約・報告・製品・販売・実用化・再利用（実務・経済活動） |
| **B** 会話・日常 | 友達・家族との交流、日常の動作・感情 |
| **E** 文化・地域 | 伝統・信仰・地場産業など文化そのもの |
| **A** 汎用（デフォルト） | 性格・様子・程度・感覚、モノの性質など場面を選ばない語 |

優先度：**F ＞ D ＞ C ＞ B ＞ E ＞ A**

判定の鉄則：
- 背景装飾に引っ張られない（「研究設備に恵まれ」で正解語が「恵まれ」→ A）
- 同じテーマでも正解語で割れる（環境系：「生分解性」→A、「実用化」→C）
- 現代日本の一般常識はAに倒す（ゴミ分別など、根底が科学技術でも生活常識ならA）
- 迷ったら A

**STEP 2：難易度で該当ブロックを開く**

- グループA〜E → `closing_patterns_ALL.md` の該当difficulty（1〜5）のブロック
- グループF → `groupF_closing_patterns.md`。**Fは難易度ではなく深刻度**（軽微/中度/重度）で分岐

**STEP 3：該当グループのパターンから1つ選び、そのまま末尾に置く**

- 選んだ〆はライブラリの文言のまま使う（ルビ込み。改変しない）
- 別問題なら同じパターンの再利用OK。同じバッチ内では直前と違うものを選ぶ
- 解説本体の末尾に `<br>` で繋ぐ

### 例

```
正解語「更新」→ 意味は「契約の更新」＝実務 → グループC
difficulty 3 → closing_patterns_ALL.md の「難易度3 > C：ビジネス」から選択
→ 「ビジネスメールや公式（こうしき）文書に頻出（ひんしゅつ）。ここで落とさないようにしましょう。」
```

```
正解語「処置」→ 意味は「応急処置」＝医療・救急 → グループF
→ groupF_closing_patterns.md で深刻度判定：重度 → パターン15〜20から選択
→ 「救助（きゅうじょ）や処置（しょち）に関わる言葉。いざという時に必ず役立ちます。」
```

## 7. ルビの基準

- **N2以上の漢字を含む語のみ**にルビを振る
- N3以下（意味・問題・言葉・注意・仕事・時間 など）には振らない
- 形式は `漢字（かな）`。`<ruby>` タグは使わない
- 語単位で振る：`状態（じょうたい）` `環境（かんきょう）` `契約（けいやく）`
- 送りがなのある語は読む部分だけ：`保（たも）つ` `譲（ゆず）る`

## 8. バリデータ【毎バッチ必須】

**目視では絶対に見つからないエラーが出ます。** 729問の作業中、解説にロシア語・韓国語・英語が計4回混入しました。スクリプトで機械的にチェックし、**エラーがあればマスターに保存しないこと。**

| # | チェック内容 |
|---|---|
| 1 | 解説冒頭の `「〜」` が、出題語または `correct_answer` と一致するか |
| 2 | `correct_answer` が `option_1`〜`option_4` のいずれかと完全一致するか |
| 3 | `<br>` が3つ以上あるか |
| 4 | **日本語以外の文字（ラテン・キリル・ハングル）が混入していないか**（`N2` `IT` `SNS` 等の許容リストを除く） |
| 5 | バッチ内で同じ解説文が重複していないか |
| 6 | 厚め枠の指定問が実際に厚くなっているか／通常枠が長くなりすぎていないか |
| 7 | `correct_answer` を誤答例として挙げていないか |

エラーが出たら修正して再実行。**エラーゼロで初めて保存する。**

---

## 9. 禁止事項

- ❌ **誤答選択肢の羅列**（「『けんさく』『かんさく』は間違った読み方です」）
  → 誤りを並べるより、正しい紐付けを一本示す
- ❌ **存在しない語の誤答に言及すること**（「着様」「千用」「試策」など）
  → 実在する語の誤答（証明↔照明、適応↔適用）のみ触れる
- ❌ 閉じの文を自分で作文すること（必ず〆文ライブラリから選ぶ。§6参照）
  → ただし同一バッチ内で同じパターンを連続使用しない。グループ判定を正しく行い、単調な繰り返しを避ける
- ❌ 「したがって、正解は○○になります」という締め（冗長）
- ❌ N5相当の語へのルビ
- ❌ **解説文そのものをスラングや硬い文体で書くこと**
  → 解説の文体はN3相当で固定。スラングや年配表現は「解説される対象」として置く
- ❌ difficulty 値の変更（再採点は別作業）
- ❌ 問題文・選択肢の変更（Phase-2 の担当）

## 10. Phase-2 からの申し送り（添付を確認）

| ファイル | 使い方 |
|---|---|
| 頻出語リスト（出現回数つき） | 5回以上＝厚め枠の対象を決める |
| 同音異義語の候補 | § 5-2 の材料。**不適切なものが混ざるので必ず目視で除く** |
| 字形が似たペア | § 5-5 の材料 |
| 問題文中の難語リスト | § 4 の切り口 #15 の材料 |
| Phase-2 の修正ログ | 直った問題文を確認する（古い文で解説を書かないため） |
| 〆文ライブラリ（`closing_patterns_ALL.md`／`groupF_closing_patterns.md`） | § 6 の閉じの文はここから選ぶ。自作しない |

## 11. 品質の目安（729問での実績）

| 指標 | 実績 |
|---|---|
| 解説のユニーク率 | **100%**（729/729） |
| 平均文字数 | 131字（99〜231） |
| ルビ入りの解説 | 690/729問（95%） |
| バリデータ検出エラー | 4件（すべて修正後に保存） |

**解説のユニーク率100%は必達です。** 1件でも重複していたら、切り口の割り振りが足りていません。
