# JLPT 問題データ 品質チェック（Phase-2）作業プロンプト

Phase-1 で生成した問題データに対し、重複と品質の問題を検出・修正する工程です。
**この工程を完了させてから Phase-3（解説文作成）に進んでください。** 順序を逆にすると、壊れた問題文に対して解説を書くことになり、二度手間になります。

---

## 0. 依頼文（そのまま貼る）

添付の問題データ（JSON / TSV）について、Phase-2 の品質チェックを実施してください。

- Part A（機械検出）はスクリプトを書いて実行し、結果をレポートしてください
- Part B（目視確認）は100問ずつ区切って進めてください
- 修正は Part C のルールに従い、マスターファイルに直接反映してください
- `explanation` 列は触らないでください（Phase-3 の担当です）

---

## 1. データ構造

```json
{
  "question_id": "JLPT_LK_N2_001",
  "category_lv1": "言語知識",
  "category_lv2": "文字",
  "category_lv3": "漢字読み",
  "difficulty": 3,
  "question_text": "契約を<u>更新</u>する。",
  "option_1": "こうしん", "option_2": "こうじん",
  "option_3": "くんしん", "option_4": "ぐんしん",
  "correct_answer": "こうしん",
  "explanation": "（Phase-3で作成）"
}
```

- `category_lv3` は `漢字読み`（漢字→読み）または `表記`（読み→漢字）
- `question_text` の `<u>` タグが出題箇所
- 「出題語」＝ `<u>` タグの中身

---

# Part A：機械検出（スクリプトを書いて実行する）

以下をすべてチェックし、件数と該当 `question_id` を一覧で出してください。**1つでも該当があれば必ず報告すること。** ゼロ件でも「ゼロ件」と報告してください。

## A-1. データの整合性（致命的・必ず修正）

| # | チェック内容 |
|---|---|
| 1 | `correct_answer` が `option_1`〜`option_4` のいずれかと完全一致するか |
| 2 | 選択肢4つがすべて異なる文字列か |
| 3 | `question_id` が重複していないか |
| 4 | `question_text` に `<u>...</u>` が1組だけあるか |
| 5 | **`表記` の下線部にひらがな以外（漢字）が混ざっていないか** ← 答えが見えてしまう重大不具合 |
| 6 | `漢字読み` の下線部に漢字が含まれているか |
| 7 | `difficulty` が 1〜5 の整数か |
| 8 | 必須カラムに空欄がないか |

## A-2. 重複の検出

| # | チェック内容 | 判定の目安 |
|---|---|---|
| 9 | `question_text` の完全一致 | 1件でもあれば要対応 |
| 10 | **`question_text` の近似重複** | 編集距離を計算し、**差が3文字以内**のペアを列挙する |
| 11 | 出題語（`<u>`の中身）の出現回数 | 上位30語を出す |
| 12 | ユニーク出題語数 ÷ 総問題数 | **70%を下回ったら警告** |
| 13 | 100問ごとのユニーク出題語数の推移 | 後半で落ちていないか |
| 14 | 誤答セット（4選択肢の組み合わせ）の重複 | 使い回しの検出 |

**過去の実績値（参考）**: 729問でユニーク語297語（41%）。301番以降は100問あたりユニーク41〜59語まで低下。「な」1文字、読点1つしか違わない完全重複ペアが十数組。

## A-3. 出題内容の妥当性

| # | チェック内容 | 方法 |
|---|---|---|
| 15 | **常用漢字外の字**が出題語に使われていないか | 常用漢字表と照合 |
| 16 | **誤答選択肢の実在率**（表記のみ） | 辞書（JMdict）で照合。`pip install jamdict jamdict-data` |
| 17 | 同音異義語の候補があるのに誤答に使われていない語 | 辞書で同一読みの一般語を検索 |
| 18 | **同一語で `difficulty` が割れていないか** | 2段階以上の開きがあれば列挙 |
| 19 | `difficulty` の分布 | 1〜5が偏りすぎていないか |
| 20 | 問題文の長さの分布 | 平均・最小・最大。同じ長さに集中していないか |
| 21 | 問題文の冒頭6文字が一致するもの | 3件以上あれば列挙 |
| 22 | 文末表現の分布 | 「〜した」等に偏っていないか |

**過去の実績値（参考）**: 表記問題の誤答1,059個のうち実在語は102個（10%）。「苦戦」が difficulty 5、「確認」が問題により 2 / 4 / 2 と割れていた。

## A-4. 外部データの入手先

- **辞書（同音異義語・実在語判定）**: `pip install jamdict jamdict-data --break-system-packages`
- **漢字構成（字形が似たペアの検出）**: `https://raw.githubusercontent.com/cjkvi/cjkvi-ids/master/ids.txt`
  - 部品が1つだけ違うペアを抽出する。除／徐、績／積、防／妨、経／軽、録／緑、破／波、講／構、販／板、編／偏 など

# Part B：目視確認（100問ずつ）

**機械では検出できない項目です。** 100問ずつ区切って読み、該当を報告してください。

## B-1. 日本語としての自然さ ← 最重要

修飾語がどこにかかるかを特に確認してください。**声に出して読んで違和感がないか**が基準です。

過去に見つかった実例：

| 内容 | 何が問題か |
|---|---|
| 事故の**計画的な**対策を講じる | 「計画的な事故」と読めてしまう |
| 相手の立場に立って**威力**を発揮する | 「威力」が文脈に合わない |
| 先生の質問に**応えて** | 質問への返事は「答えて」 |
| 和やか**にな**調和を保つ | 誤字 |
| 努力が**身**を結び | 「実を結び」の誤り |

## B-2. 誤答選択肢の妥当性

- **誤答が正解になり得ないか**（複数正解の疑い）
- 誤答が簡単すぎて消去法で解けてしまわないか
- 逆に、誤答が正解と区別できないほど紛らわしくないか

## B-3. difficulty の妥当性

- **語の難しさ**で決まっているか（文脈が難しいだけで上がっていないか）
- A-3 の #18 で検出された「同一語で割れているもの」を優先的に見る

## B-4. 出題語がN2の範囲か

- 常用漢字外は A-3 #15 で機械検出済み。それ以外に、明らかにN1以上の語がないか

---

# Part C：修正のルール

## C-1. 必ず修正するもの

1. A-1 の整合性エラー（全項目）
2. 日本語として不自然な問題文（B-1）
3. 誤字・脱字
4. 複数正解になっている問題（B-2）
5. 常用漢字外の出題語 → **問題ごと差し替える**

## C-2. 修正するか判断が要るもの

| 対象 | 判断の指針 |
|---|---|
| **完全一致・近似重複の問題文** | 出題語は残し、**文脈（主語・場面・文型）を書き換える**。問題を削除しない |
| **出題語の重複そのもの** | **削除しない。** 頻出語は学習価値が高いため残す（Phase-3 で解説を書き分ける） |
| difficulty の不整合 | 同一語は揃えるか、文脈差を説明できる範囲（1段階以内）に収める |
| 誤答の実在率が低い | 表記問題で、実在する同音異義語に差し替えられるものは差し替える |

## C-3. 修正しないもの

- `explanation` 列 ← **Phase-3 の担当。一切触らない**
- 選択肢の並び順 ← 運用時にシャッフルされるため無意味
- 問題の並び順 ← 同上

## C-4. 修正の適用方法

- マスターファイルに直接反映する（中間ファイルは作らない）
- 修正後、**Part A のスクリプトを再実行**して、新たなエラーが出ていないことを確認する
- 修正した `question_id` と修正内容の一覧を残す

---

# Part D：資産化（次工程・次回への申し送り）

**この工程の出力は「レポート」ではなく「次の入力」です。** 以下を必ずファイルとして出してください。

## D-1. 修正の成果物

1. **検出レポート（md）** — Part A の全項目の結果、Part B の指摘一覧
2. **修正済みマスターファイル** — 修正を反映したもの
3. **修正ログ** — 何を、なぜ直したか

## D-2. Phase-1（次回の問題生成）へ返すもの

| ファイル | 中身 | 使い方 |
|---|---|---|
| **既出語リスト** | マスターから抽出した全出題語（カンマ区切り） | 生成プロンプトの【既出語リスト】にそのまま貼る |
| **語彙の偏りプロファイル** | 出題語を分野別に分類した集計（仕事／報道／生活／学校／自然／医療 など） | 手薄な分野を次回の生成指示に加える |
| **使用済み誤答ペア** | 使った同音異義語ペア・字形ペアの一覧 | 次回は未使用のペアを優先させる |
| **difficulty別 語リスト** | どの語がどの難易度で出たか | 採点のブレを防ぐ基準として渡す |
| **使用済み文型** | 問題文の冒頭パターン・文末表現の一覧 | 次回は別の型を使わせる |
| **失敗実例集** | 不自然だった問題文と「何が問題か」 | 生成プロンプトに**具体例として**追記する |

**「失敗実例集」がいちばん効きます。** 抽象的に「自然な日本語で書け」と指示しても効きません。「事故の**計画的な**対策を講じる ← 計画的な事故と読める」という実例を1行入れるほうが、同じ失敗を確実に減らせます。

**既出語リストは必ずマスターから機械抽出してください。** 各バッチの自己申告を貼り足していく方式は、貼り忘れと申告漏れで必ず崩れます。

## D-3. Phase-3（解説文作成）へ渡すもの

| ファイル | 中身 |
|---|---|
| **頻出語リスト** | 出題語と出現回数。5回以上の語には印を付ける |
| **同音異義語の候補** | 辞書検索の結果。**教材に不適切なものが混ざるので自動挿入は禁止**と明記する |
| **字形が似たペア** | 部品が1つだけ違う組み合わせ（除／徐 など） |
| **問題文に含まれる難語** | 出題語以外で、解説の材料になりそうな語（恣意的・入念・仇となる など） |

## D-4. 蓄積の運用

D-2 と D-3 は**上書きではなく、版を重ねてください。** 3回分並べれば、ユニーク語率や誤答の実在率が改善しているかが一目で分かります。

| 指標 | 初回（729問） | 2回目 | 3回目 |
|---|---|---|---|
| ユニーク出題語率 | 41% | | |
| 誤答の実在率（表記） | 10% | | |
| 完全・近似重複ペア | 十数組 | | |
| 常用漢字外の出題語 | 2語（炙・斡） | | |
| difficulty の割れ | 4語以上 | | |

# 補足：この工程で分かること

Phase-2 は「直す」だけの工程ではありません。**生成プロンプト（Phase-1）の弱点が数字で出てきます。**

- ユニーク語率が低い → 既出語リストの渡し方に問題がある
- 誤答の実在率が低い → 誤答生成の指示が効いていない
- 問題文の冒頭が揃う → 多様化の指示が効いていない
- difficulty が偏る → 難易度指定が効いていない

これらは Phase-1 のプロンプトにフィードバックしてください。Phase-2 で毎回大掃除をするより、入口を直すほうが安上がりです。
