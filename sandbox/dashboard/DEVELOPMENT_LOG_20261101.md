## 5. Bike：時系列分析の追加

新たに`sample_dsbd_bike.py`を作成し、抽出・集計・前年対応を`bike_timeseries.py`へ分離した。初期期間は前年と比較できる2012年とした。

| 機能 | 実装した動作 |
| --- | --- |
| ズーム・レンジスライダー | グラフの表示範囲だけを変更する |
| 表示期間を全体に適用 | 境界を含む日単位で、KPI・全グラフ・明細・CSVへ適用する |
| 集計粒度 | 月・週・日・時間を切り替える |
| ドリルダウン | 月・週の点→日別、日の点→時間別。履歴から元の期間・粒度へ戻る |
| 指標・集計方法 | 全利用・一般・登録、合計・観測1行あたりの平均を切り替える |
| 前年比較 | 同じ月日へ前年値を対応させ、同じ天候・勤務日フィルターを適用する |
| 移動平均・基準線 | 日別値、7暦日移動平均、抽出日別値の平均を表示する |
| 欠損 | 未観測枠を0へ置換せず、元の時間別CSVにない時間枠を別途表示する |

日別と時間別は同じ貸出の別集計であり、足し合わせない。時間別へ進む場合は必ずhour.csvを使い、日別値から24時間分を生成しない。

週は月曜始まりで、選択期間の端にある週・月は期間内の行だけを集計する。平均の分母は実際に抽出された元データの行数。日別と時間別の平均は分母が異なる。

前年にない2月29日や未収録の2010年は空白とし、前年の曜日が一致する比較ではないことを画面に記載した。移動平均は選択期間内の直近7暦日すべてが観測されている場合に限り表示する。

元の時間別CSVの未観測枠は全期間165時間、2012年50時間。天候・勤務日フィルターによる除外とは別に計算する。

## 6. ローカルでのデータ更新・接続・出力

利用形態について「まず分析画面とローカル動作を充実」と回答を受け、この範囲で機能を追加した。

### 6.1 CSV／SQLiteと再読込

`bike_data_service.py`を追加した。

- SQLiteは初回にCSVから`.local/bike.sqlite3`を作り、その後はDB自体を読む。CSV変更をDBへ自動同期しない。
- 手動再読込と、既定60秒間隔の定期再読込を提供する。
- 読込確認時刻をJSTで表示する。現在の実データの発生時刻とは区別する。
- 必須列、整数・範囲、日時・IDの重複、回数、日別・時間別の日次合計を検証する。
- 再読込失敗時は前回のデータ版を保持し、理由を表示する。
- SQLiteの両テーブルを同じ読取トランザクションで取得する。

ローカルDBとPythonキャッシュをGit管理から除外した。テストのDB更新は一時フォルダーで実行し、元CSVや実際のローカルDBへ変更を加えていない。

### 6.2 データ版、キャッシュ、表の転送

データ内容のハッシュを版として使用し、同じ内容の再読込では集計結果を再利用する。内容が変わった場合は別のキャッシュキーで計算する。

- 公開サンプルの集計結果を最大16条件分、プロセス内のLRUキャッシュへ保存。
- スナップショットは最大8版。期限切れは再読込を案内する。
- 利用者の選択状態は共有しない。キャッシュ結果の複製を返し、呼出側の書換えから保護する。
- CSV保存もその画面が参照しているデータ版を使い、途中の更新で明細が入れ替わることを避ける。
- 表は全データをサーバーで並べ替え、1ページ15行だけを転送する。CSVは抽出全行を保存する。

単一Pythonプロセスの学習用サンプルであり、分散キャッシュや複数ワーカー間の版管理を実装したものではない。

### 6.3 日本語PNGと印刷・PDF

グラフのカメラボタンからPNGを保存できるようにし、日本語のタイトル・軸ラベルを画像で確認した。

印刷ボタンはブラウザの印刷機能を呼ぶ。PDFは印刷先で選択する方式で、表は表示中のページのみ。全明細を整形した帳票や定期配信ではない。PDFの日本語テキストも確認し、PNG保存直後の通知が印刷へ混入しないようCSSを調整した。

## 10. 判断の記録と振り返り

- **既存実装を保ちながら学習用の入口を追加した。** Irisの選択ロジックを再利用し、sample名の画面でコードの役割を説明した。
- **グラフの選択元には候補を残した。** 自身の選択だけを除いた範囲で描画し、選択の拡大・変更を可能にした。他のグラフ・KPI・表・CSVには全条件を適用する。
- **表示上のズームとデータ抽出を分けた。** 「拡大しただけで全体の集計まで変わる」という曖昧さを避け、適用ボタンで全体へ反映する仕様とした。
- **欠損・0・未収録を区別した。** Bikeの時間不足や前年の2/29を架空の0として補完しない。
- **公開サンプルの計算結果と個人の操作状態を分けた。** 共有キャッシュはデータ版と条件をキーとし、利用者の選択をグローバル変数へ書き戻さない。
- **日本語表示は実際の出力も確認した。** 画面だけでなくPNGを目視し、PDFの文字を抽出した。フォントが異なるすべての端末を確認したわけではない。
- **テストの失敗を実装不良と混同しないよう切り分けた。** 主グラフとスライダーの複製点の数え違い、非同期描画・ホバー確定前のクリック、解除ボタンの指定を調べてテストを修正した。一方、リセット時のズーム解除や印刷への通知混入は実装も調整した。
- **商用BIとの比較は機能と運用を分けて考える。** 基本の分析操作を実現できても、権限・監査・配信・保守・複数利用者の運用まで確認したことにはならない。

### 11.3 再開時の進め方の候補

再開時は本ログ、機能確認一覧、各テスト記録から現状を確認し、保留項目をどこまで仕様化するか決める。

- **学習用サンプルを少し広げる場合**：Bikeの状態復元・共有を候補にする。既存Irisとの比較ができ、接続先や配信先を用意せずに検討できる。
- **具体的な分析処理を追加する場合**：処理時間を測り、必要ならバックグラウンド実行へ進む。重い処理がない段階でジョブ基盤だけを増やさない。
- **社内運用へ進む場合**：先に利用者・権限・接続先・同時利用数を決め、認証、外部接続、共有キャッシュ、負荷試験を一緒に設計する。

どれも推奨候補であり、着手予定の確定ではない。保留解除時に、対象機能、期待する操作、完了条件、必要な接続・運用条件を小さな仕様にまとめてから実装する。
