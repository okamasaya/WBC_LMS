# 正誤を中心にした補助2項目BKT・フラット試作

モデル版：`bkt-assisted-flat-v1`。正誤を主観測、自信度を観測の重み、解説後の理解度を学習遷移の補助として扱う、手動仮定の実験モデル。

## 1. 今回の範囲

利用者の「正誤を中心に、自信度と理解度を補助として扱う」という方針を採用した。3項目の等重み平均ではなく、BKTの処理順を保って補助する。

「フラット」は初版では各回答を同じ初期習得確率から独立に評価する意味とした。StudentID・SkillID・回答日時を系列更新には使わず、履歴をつなげない。既存のmodel.pyによる正誤のみの標準BKTは変更しない。

この拡張の数値は仮定したモデル内の確率であり、実測の理解度や検証済みの習得確率ではない。実ログによるパラメータ学習・予測精度の評価、論文との照合は未実施。

## 2. 入力項目と向き

| 項目 | 値 | 意味・取扱い |
|---|---|---|
| IsCorrect | True / False（CSVのTRUE/FALSE、1/0も受付） | 問題の正誤。未入力・不正値は理由付き除外 |
| ConfidenceLevel | 1, 2, 3, 4 | 回答時の自己申告。1=自信がある、2=少し自信がある、3=やや不安、4=直感に近い |
| UnderstandingLevel | 0, 1, 2, 3 | 解説後の自己申告。0=全然分からない、1=まだ少し分からない、2=だいたい理解できた、3=理解できた |
| IsAnswered | 任意。省略時True | Falseの行は推定しない。未回答と誤答を混同しない |
| ResultID | 任意 | 同一ID・同一3項目は重複除外。異なる3項目や識別情報がある場合は採用版の確認を求める |
| StudentID・SkillIDなど | 任意 | 元の情報として保持するが、今回の確率の計算には使わない |

補助項目の未入力は倍率1（補助なし）とする。理解度0は未入力と区別する。原本を書き換えず、モデル出力を別に作る。正規化後の数値と異なる版のログを混ぜて勝手に平均しない。

## 3. 仮パラメータ

標準BKTと同じ記号を使う。

| パラメータ | 初期値 | 意味 |
|---|---:|---|
| P(L0) | 0.20 | 各回答の事前習得確率 |
| P(T) | 0.10 | 基本の学習遷移確率 |
| P(G) | 0.25 | 未習得でも正解する確率 |
| P(S) | 0.10 | 習得済みでも誤答する確率 |

これらは仮値で、4択だからP(G)=0.25が妥当と実証されたわけではない。画面では4パラメータを変更して挙動を比較できる。P(G)+P(S)<1を条件とする。

補助設定の初期値：

| 自信度の生値 | 観測重み w |
|---|---:|
| 1（高） | 1.50 |
| 2 | 1.00 |
| 3 | 0.75 |
| 4（低） | 0.50 |
| 未入力 | 1.00 |

| 理解度の生値 | 学習遷移倍率 a |
|---|---:|
| 0（低） | 0.25 |
| 1 | 0.50 |
| 2 | 0.75 |
| 3（高） | 1.00 |
| 未入力 | 1.00 |

これも未校正の手動仮定で、段階間の差や倍率は実ログから推定していない。理解度0を学習ゼロと断定せず、初期案では基本学習遷移の25%を残す。未入力と最高理解度はこの初期設定では同じ倍率だが、欠損フラグを別に出力して区別する。

## 4. 計算の順序

事前習得確率をpとする。

### 4.1 回答前の正答予測

```text
P(correct before answer) = p × (1 − P(S)) + (1 − p) × P(G)
```

回答後に入力される自信度と、解説後の理解度はこの値へ使わない。学習・評価時に解説後の情報を同じ回答の予測へ混ぜると、未来情報を使うことになる。

### 4.2 正誤の観測と自信度

正解なら`q_known = 1 − P(S)`、`q_unknown = P(G)`。
不正解なら`q_known = P(S)`、`q_unknown = 1 − P(G)`。

```text
p_observed = p × q_known^w
             / (p × q_known^w + (1 − p) × q_unknown^w)
```

これは正誤尤度に重みを付けるpower / tempered Bayesの形を使った仮説で、標準BKTの実装そのものとは区別する。自信度の自己申告がどの程度信用できるかを実証したモデルではない。

初期設定では高自信の正解で上方更新、高自信の誤答で下方更新が強くなる。低自信なら更新が事前確率寄りになる。実装では対数オッズを使い、極端な値でも指数演算のオーバーフローを避ける。

### 4.3 解説後の理解度と学習遷移

```text
T_effective = P(T) × a
p_after = p_observed + (1 − p_observed) × T_effective
```

理解度はこの段階だけに使う。正誤観測後のp_observedや回答前の正答予測へ逆流させない。

### 4.4 同一スキルを仮定した次問の比較値

```text
P(next correct) = p_after × (1 − P(S)) + (1 − p_after) × P(G)
```

同じスキル・出題条件を仮定したモデル上の比較値。今回SkillIDを使わず各行を独立評価しているため、次に出す任意の問題について正答を保証する値ではない。

## 5. 標準BKTとの比較例

既定パラメータ、正解・自信度1・理解度3の例：

| 段階 | 正誤のみ・標準BKT | 補助あり試作 |
|---|---:|---:|
| 初期 | 0.200000 | 0.200000 |
| 正誤観測後 | 0.473684 | 0.630673 |
| 学習遷移後 | 0.526316 | 0.667606 |

自信度・理解度がともに未入力なら、補助あり試作は同じ1回答に対する標準BKTと一致する。標準BKTの継続した履歴と、独立回答の本モデルをそのまま比較することはしない。


APIの利用例：

```python
from sandbox.dashboard.bkt.assisted_model import estimate_flat

result = estimate_flat([
    {'IsCorrect': True, 'ConfidenceLevel': 1, 'UnderstandingLevel': 3},
    {'IsCorrect': False, 'ConfidenceLevel': 4, 'UnderstandingLevel': 0},
])
# result['records']：入力＋推定値・仮定・欠損フラグ
# result['excluded']：除外行と理由
# result['parameters'] / ['assumptions']：再現に必要な仮定
```

入力順・StudentID・SkillIDはこの初版の確率へ影響しない。結果を次の回答の事前確率へ渡さない。回答の履歴、スキルごとのパラメータ、Djangoのアップロード／保存は別の仕様として扱う。

## 7. 今後の検証候補

- 実ログで自信度と正誤、解説理解度と次回回答の関係を観察する。
- 標準BKT、自信度だけの補助、理解度だけの補助、両方の補助を比較する。
- 重み・倍率の学習や校正を行う場合は、学習者・時系列を考慮して学習用と評価用を分ける。
- 予測対象を「次の同一スキルの正誤」とするなど、時点と評価指標を先に定義する。
- 履歴接続・忘却・スキル粒度・解説閲覧の扱いは、論文と実データを確認して決める。

今回は合成32パターンと既存の架空ログを使った挙動確認まで。実際の生徒の習得状態、将来正答、成績判断の妥当性を確認したものではない。
