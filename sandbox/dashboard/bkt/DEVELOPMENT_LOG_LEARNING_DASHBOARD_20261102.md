# 開発記録：N2学習ダッシュボード初版とブレイクポイント（2026-11-02）

## 依頼と方針

利用者より、SQLiteを主な入力として継続し、同じデータのCSVを控えとして用意してもよいこと、数値・各大問題の正解率／理解度・サマリーを参考画像のように表示したいこと、今回をブレイクポイントにすることが示された。

画像はN1で読解・聴解等を含むが、今回のデータはN2言語知識（文字・語彙・文法）である。この9大問題と5回150回答を対象とし、既存のモデル検証画面を保持したまま、新しいファイルへ学習結果をまとめる画面を作った。

## 今回の完了範囲

- learning_dashboard.py：8056の新画面。左メニュー、条件、数値カード、大問題比較、推移、サマリー、履歴、数値表、明細と出力。
- dashboard_data.py：SQLite／控えCSVの読込、期間・学習者・大問題フィルター、指標別集計、5表のCSV書出し。計算はDashに依存しない。
- learning_assets/learning.css：新画面専用の配色・配置・スマートフォン対応。旧画面のassetsから分離。
- SQLiteと同内容のCSV5表とmanifest。SQLiteの行・列・型に対応し、同じ入力・レポートになることを検証。
- 指標・起動・連動・出力の[説明書](LEARNING_DASHBOARD.md)、開発・テスト記録、画面画像。

モデルの式・パラメータは変更しない。8055は3項目モデルの条件確認・実CSVアップロード、8054は既存の標準BKT確認、新しい8056は学習結果のサマリーとして役割を分けた。

## 表示と意味の固定

1. 数値カード：正解率、自己申告の解説後理解度0〜3、独立回答モデル試算の平均、平均回答時間、実施回数と回答件数。
2. 大問題別比較：既存SkillIDに対応する9大問題、直近3回の正解率。棒選択で条件を連動。
3. 推移：実施日ごとの自己申告理解度／モデル試算／正解率を切り替える。モデル試算を累積習得率・信頼区間として表示しない。
4. サマリー：最新回、前回との差、正解率が低い大問題と件数、自信度1・2での誤答数。集計ルールによる振り返りで、AI生成の推薦ではない。
5. 履歴・数値・明細：条件に合う表示とCSV出力。モデル版・パラメータ・重み・選択条件はJSONで保存。
6. データ状態：未回答、自己申告未入力・不正、推定除外の件数を表示。理解度0を欠損へ変換しない。

全体正解率は有効回答の正答数／回答数とし、大問題ごとの率の単純平均を使わない。補助項目が不正な行はモデル推定から外すが、有効な正誤は正解率の集計へ残す。平均理解度は有効な自己申告を分母とする。

## 再開用の起動

リポジトリ直下なら`python -m sandbox.dashboard.bkt.learning_dashboard`。sandbox/dashboardからなら`python -m bkt.learning_dashboard`。sandbox/dashboard/bktの中にいる場合は`cd ..`してから後者を使う。`-m`に.pyは付けない。

http://127.0.0.1:8056 を開く。DBサービスの起動は不要で、既存のPython依存パッケージを使う。[操作と指標の説明](LEARNING_DASHBOARD.md)を参照する。
