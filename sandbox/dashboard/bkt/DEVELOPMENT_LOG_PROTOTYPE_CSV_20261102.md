# 開発記録：現行prototypeの実施結果CSVとBKT入力（2026-11-02）

## 依頼と判明したこと

利用者より「問題を実施し、解説後のサマリーレポートと合わせて出力するCSV群をBKT入力に使う目的だった。先ほどのモックと項目が一致するか確認したい」との依頼があった。

最初のモックは共通のモデル入力項目を持つ独自の保存用CSVで、現行のQuestionResult41列・Session26列の完全な複製ではなかった。元のモックはそれぞれ33列・21列。正誤・自信度・理解度の向きと値は一致していたが、この用途では現行出力全体の照合も必要だった。

## 対応

1. Actual・JSON版Drillと共通の結果生成・解説後更新・確定・出力処理を調査した。
2. 現行の列定義をそのまま参照し、ResultData・ResultReview・ResultReportをNode.jsで実行する生成補助処理を追加した。現行prototypeソースは変更しない。
3. 既存モック600回答を同処理で再出力し、prototype_csv/へ互換版を追加。元の保存用CSV、SQLite案、過去の記録は保持する。
4. 20回を結合した互換CSV、1回分の3種出力＋レポート、ID対応表、合成識別とハッシュを含むmanifestを保存した。
5. 8055のモック選択を互換QuestionResult.csvへ切り替えた。
6. 実際の現行画面を操作して理解度0/3を入力し、確定後の3種CSVをダウンロード。サマリーレポートとの整合性と、両モデルへの接続を検証した。

## 重要な取込条件

各問の入力はQuestionResult CSVか、統合Raw CSVのQuestionResult節。Sessionはサマリー、レポートは人間・AI向けのため、各問のモデル入力としては使わない。

現行設定はStudentIDが空欄となる。独立回答の補助モデルはそのまま処理できるが、学習者別履歴を使う標準BKTは本人への対応付けが必要。単一学習者と確認したID補完は既存APIで可能。複数人の空欄を勝手に一人へまとめない。

補助モデルへはCSVパーサーの結果を直接渡す。標準BKT用の正規化では補助項目の版違いを検出しないため、補助モデルの前処理に通さない。解説後に再確定したCSVは、同じResultIDの理解度が変わることがあるので、採用版を選ぶ必要がある。

現行CSVは解説閲覧・理解度記録の時刻を持たない。元のモックにある追加イベント時刻は合成した検討用情報で、現行ログから取得できたものではない。
