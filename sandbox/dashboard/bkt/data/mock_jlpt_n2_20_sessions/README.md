# JLPT N2・言語知識：20回分のモック学習ログ

**架空の学習者1人・20回・各30問、計600回答。** 実際の学習者の記録ではありません。問題定義とスキルIDは既存リポジトリのものを参照し、回答・自信度・理解度・日時だけを合成しています。

## 前提と件数

- 生成版：jlpt-n2-mock-v1、モックスキーマ版：1.0、乱数seed：20261102。
- 合成実施日：2026-09-01〜2026-10-28、3日おき、19時開始（JST）。
- 現在の開発用設定に合わせ、9スキルから各回30問、制限40分以内。公式JLPTの全問構成や尺度得点を再現していません。
- v1は全問回答済み、自信度・理解度の欠損なし。未回答・欠損の検証は既存モデルの単体テストで別に行います。
- 600回答、500種類の問題。回内の問題重複なし、回をまたぐ再出題はあります。
- 正答328件、誤答272件。高自信（1・2）の誤答78件、低自信（3・4）の正答89件を含みます。

## ファイルと関係

| ファイル | 行数（見出し除く） | 内容 |
|---|---:|---|
| Student.csv | 1 | 架空学習者のID・表示名 |
| Skill.csv | 9 | 既存confのスキルと1回あたりの出題数 |
| Question.csv | 500 | 使用した既存問題のID・問題文・選択肢・正解位置・出典パス |
| Session.csv | 20 | 各回の開始・終了・解説完了、件数と正答率 |
| QuestionResult.csv | 600 | 1問1行。正誤・自信度・解説理解度と各時刻 |
| DataDictionary.csv | — | 全列の型・キー・意味・v1の欠損方針 |
| DatasetManifest.json | — | 生成条件、元データのハッシュ、件数、分布、CSV等のハッシュ |
| schema.sql | — | 将来のSQLite移行用のスキーマ案。今回の一時DBで投入検証済み |

すべてのCSVはUTF-8 BOM付き。既存BKTの取込へ渡すのは**QuestionResult.csvだけ**です。Student・Skill等は参照用で、回答CSVではありません。公式出力と共通の列名を使っていますが、公式QuestionResultの全列を再現したものではなく、モック独自の追加時刻・版情報を持ちます。

```text
Student ── Session ── QuestionResult ── Question ── Skill
                学習者・回次・出題順と、問題／スキルの対応を検証
```

SessionNumberやStudentID、スキル名等は、CSV単体で確認しやすいよう回答行にも持たせています。SQLite案では外部キーに加え、受験と学習者、問題とスキルの組合せも制約で照合します。

## 最初に見る列

- IsCorrect：TRUE/FALSE。
- ConfidenceLevel：1=自信がある、2=少し自信がある、3=やや不安、4=直感に近い。
- UnderstandingLevel：0=全然分からない、1=まだ少し分からない、2=だいたい理解できた、3=理解できた。
- StudentID・SessionID・SessionNumber・QuestionSequence・QuestionID・SkillID：学習者、回次、順序、問題とスキルの識別。
- IsSynthetic：Student・Session・QuestionResultで常にTRUE。実績データと区別します。
- DatasetID・MockSchemaVersion：生成条件と列定義の版を追跡します。

正答位置と選択位置は1〜4。選択肢はシャッフルしていません。Difficultyは既存問題の1〜5を使用。ScoreRateは単純な正答率を0〜100へ四捨五入した値で、JLPT公式の尺度得点・合否点ではありません。

## 時刻と未来情報の扱い

```text
問題提示 → 回答選択 → 自信度記録 → 試験終了
  → 各問の解説閲覧 → 解説後の理解度記録
```

QuestionPresentedAt、AnsweredAt、ConfidenceRecordedAt、ExplanationViewedAt、UnderstandingRecordedAtは、タイムゾーン付きISO8601（+09:00）。ResponseTimeMsは問題提示から自信度記録までです。解説・理解度は全30問の試験終了後に記録します。

ExplanationViewedAt等は、今後の分析用に追加した**合成イベント時刻**で、現在の問題実施画面がすべてを実測・出力しているという意味ではありません。

現在のフラット試作は各回答を独立評価するため、理解度を同じ回の後続回答へ引き継ぎません。将来履歴をつなぐモデルでは、解説後の情報を試験中の次問へ使わない設計が必要です。標準BKTへの600行の読み込み確認は、入力互換性・計算の実行確認であり、Actualでの学習遷移の妥当性を証明するものではありません。

## 再生成

リポジトリルートで実行します。標準ライブラリのみで生成できます。

```sh
python -m sandbox.dashboard.bkt.mock_dataset

# 別条件は別フォルダーへ
python -m sandbox.dashboard.bkt.mock_dataset --seed 7 --sessions 20 --output /tmp/jlpt_n2_mock_seed7
```

同じPython環境・入力ソース・設定・seedなら同じ内容を再生成でき、同じ内容の既存ファイルは変更しません。内容が違う既存ファイルは既定で保護し、明示的な--overwriteが必要です。READMEなど生成対象以外のファイルは上書きしません。

## 画面とSQLite

```sh
python -m sandbox.dashboard.bkt.flat_app
```

8055の画面で「JLPT N2・20回分のモック」を選ぶと600回答を読み込めます。正解328件・不正解272件の絞り込みとCSV保存を確認できます。これは履歴をつながない現行フラットモデルの表示です。

SQLiteは今回永続ファイルを作っていません。schema.sqlは単一データセットの初期案で、一時SQLiteへ5つのデータCSVを型変換して投入し、外部キー・一意性・集計を検証しています。CSVのTRUE/FALSEはSQLiteで1/0へ変換します。

列を増減する際は、MockSchemaVersion、DataDictionary、生成スクリプト内のCOLUMNS、SQLite案とテストを合わせて見直します。v1は欠損なしでNOT NULLにしています。今後欠損を追加する場合、空欄を0へ変換せずNULLの仕様を決めてから変更してください。複数のデータセットや問題定義の版を同じDBへ蓄積する設計・移行手順は次の段階です。
