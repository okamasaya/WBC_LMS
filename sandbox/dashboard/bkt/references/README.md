# BKTの参照資料・確認事項

## 今、使える資料

- [既存のモデル実装](../model.py)と[テスト](../tests/test_bkt.py)：固定パラメータによる標準BKTの更新式と期待値。
- [既存の仮パラメータ](../bkt_parameters.json)：手動仮定の値であり、学習済み・校正済みではない。
- [学習ログと出力の意味](../../../../docs/standard/results.md)：未回答、自己申告、学習者ID、スキルIDの位置付け。
- [ALP–BKTデータフローの既存記録](../../../../docs/development/School_LMS_Development_Log_20260820_Phase3.md)：Rawログと推定結果を分ける方針、パラメータと推定テーブルの整理。

これらを土台に、ファイル整理と既存計算の確認は進められる。論文本文がなくても作業を止める必要はない。

## 基本文献の候補

Corbett & Anderson, **“Knowledge tracing: Modeling the acquisition of procedural knowledge”**。

標準BKTを確認する際の基本文献候補。今回は本文を取得・照合していない。職場PCにある論文がこの文献か、忘却・パラメータ学習などを扱う別の拡張論文かを、後でタイトルから確認する。

## 後で用意できると役立つ情報

| 情報 | 確認する目的 |
|---|---|
| 論文タイトル、著者、参照したい章・式 | 標準BKTと拡張モデル、更新の順序、パラメータ学習方法を区別する |
| 匿名化した少量の学習ログと列説明 | 実際の列から正規化済みモデル入力へ対応付ける |
| StudentID・SkillIDの決め方 | 学習者とスキルごとの系列を混ぜずに追跡する |
| 回答順、セッションをまたぐ日時の仕様 | 時系列を再現し、同一時刻や再取込時の順序を決める |
| 未回答・再回答・同じ問題の反復の扱い | 除外・観測の採用条件と重複判定を決める |
| 推定結果を何に使うか | 習得状態の可視化、次問正答予測、推薦などの目的と評価を決める |
| パラメータは仮設定でよいか、実ログから学習したいか | 状態の推定とモデルパラメータの学習を別工程として設計する |

実ログがまだなければ、当面は既存の架空データで計算を確認できる。Djangoの接続情報や認証設定は、今回の整理には不要。
